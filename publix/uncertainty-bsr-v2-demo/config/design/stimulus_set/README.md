## How they were built

- Command: `npm run set:build` (`vite-node tools/build_stimulus_set.ts`), Node v25.6.0, stimulus-set-1.1.0, cloud-rsa-1.0.0.
- Inputs: `config/experiments/exp1.json` section `stimulus.cloud` (canonical JSON, SHA-256 `6d588aa95c47b08a636b004cebf0b982c8be40d354fe740bbcc1049a9a26c0d4`) and `config/design/stimulus_distribution.json` (raw bytes, SHA-256 `6a8aedf5a6f3df4e5c8ac3afee6fa84730528f34f3a42badb67e7ee5b1fc2cb5`). The sets never hash `exp1.json` as a whole.
- Counts: the union of the levels of both contexts, 24 counts (20, 24, 26, 28, 29, 30, 32, 34, 36, 38, 40, 41, 43, 44, 46, 48, 50, 52, 54, 55, 56, 58, 60, 64). Fractions of the thirds: 0.1667, 0.5000, 0.8333 (the centre of each third).
- Learning phase set `learning-S` (wave 12): the 15 levels of context S (20, 24, 26, 28, 30, 32, 34, 36, 38, 40, 43, 46, 50, 55, 64), the same nine targets each; its set id differs from the others, so every candidate seed does.
- Learning phase set `learning-L` (wave 12): the 15 levels of context L (20, 29, 34, 38, 41, 44, 46, 48, 50, 52, 54, 56, 58, 60, 64), the same nine targets each; its set id differs from the others, so every candidate seed does.
- Candidates per image: 20. Candidate j has seed `seedFrom(set_id, count, size_third, spacing_third, j)`; restarts as in `generateCloud` (largest restart count: test 0, train 0, learning-S 0, learning-L 0).
- Selection rule: r* = median hull-to-field ratio (convex hull area of the dot centres / field area) over every candidate of every target of the set, computed before any scaling. For each target, five non-negative deviations per candidate: (a) |hull-to-field ratio - r*|, (b) centroid offset from the field centre (deg), (c) |nearest-neighbour mean - median nearest-neighbour mean of the target candidates| (deg), (d) nearest-neighbour standard deviation (deg), (e) half-field imbalance = |dark - bright| summed over the left, right, top and bottom half-fields. The five quantities are computed from the candidate values as written in the file (10 significant digits). Each quantity is scaled, not centred: divided by its root mean square over the K target candidates (0 for every candidate when that root mean square is at most 1e-9 of the largest absolute value). Score = sum of the five squared scaled quantities, rounded to 10 significant digits. The kept candidate has the smallest score, so the smallest deviations; equal scores are a tie and the lowest candidate index wins. The median of an even number of values is the mean of the two middle values.
- r*: test 0.7320, train 0.7323, learning-S 0.7125, learning-L 0.7507.

## Effect of the selection

Per selection quantity (a)–(e) of the rule, means over the targets of: the mean over the target's candidates
(all candidates), the kept candidate's value (kept), and the kept candidate's rank among its target's candidates,
the share of the other candidates with a smaller value (kept rank: 0 = the smallest value, 1 = the largest; a
candidate drawn at random has 0.5). Over the five quantities and both sets the kept rank is 0.139–0.389.

stimulus-set-1.0.0 used the same five quantities but centred each one as a z-score before squaring, which kept the
candidate nearest the middle of each quantity instead of the one with the smallest deviations. 1.1.0 scales each
quantity by its root mean square without centring, so a candidate smallest on all five has the smallest score.

## Checks

`npm run set:check` (`analysis/check_stimulus_set.py`) recomputes every feature from the stored dots, the field
bound, the minimum distance, the targets against the feature table at 5.4°, the input hashes and the selection.
